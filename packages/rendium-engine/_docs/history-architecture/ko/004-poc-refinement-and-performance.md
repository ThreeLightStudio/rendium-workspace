# ADR 004: POC 고도화 및 성능 최적화 (Registry 및 데이터 표준화)

[English](../en/004-poc-refinement-and-performance.md)

## 대상 (Context)
Studio 애플리케이션의 복잡도가 증가함에 따라, 엔진의 레이어 탐색 성능 최적화와 WebGPU 렌더링의 안정성을 위한 데이터 구조 표준화가 필요했습니다. 또한, 프로젝트의 영속성(Persistence)을 위해 씬(Scene)의 직렬화 및 복구 메커니즘을 정립하고자 합니다.

## 결정 사항 (Decision)

### 1. 검색 최적화: "O(1) Layer Registry 도입"
*   **결정:** `Scene` 클래스 내부에 `Map` 기반의 레이어 Registry를 유지합니다.
*   **사유:** 기존의 $O(n)$ 선형 탐색 방식은 레이어 수가 많아질수록 UI 반응성을 저하시킵니다. Registry를 통해 ID 기반의 즉각적인 접근을 보장하여 렌더링 루프 외의 상태 조회를 최적화합니다.
*   **정합성:** `SceneMutator`를 통한 레이어 추가/삭제 시 Registry를 원자적으로(Atomically) 동기화합니다.

### 2. 가용성 표준화: "256-byte Uniform Alignment 상향"
*   **결정:** 모든 WebGPU 레이어의 유니폼 버퍼 크기를 256바이트(64 float)로 고정합니다.
*   **사유:** 112바이트(v1)는 기초적인 트랜스폼 데이터만 담기에 충분했으나, 그림자, 외곽선, 필터 등 고급 스타일 속성을 확장하기에는 한계가 있었습니다. 256바이트는 WebGPU의 정렬 제약을 완벽히 준수하면서도 미래 확장을 위한 충분한 패딩을 제공합니다.

### 3. 좌표계 통일: "1920x1080 논리적 픽셀 시스템"
*   **결정:** 엔진 내부의 모든 위치 및 크기 계산을 1920x1080 고정 해상도의 논리적 픽셀 공간에서 수행합니다.
*   **사유:** NDC(Normalized Device Coordinates) 방식은 화면 비율 변화에 대응하기 어렵습니다. 논리적 픽셀 시스템은 UI 트랜스폼 도구와 엔진 렌더링 사이의 일관된 거리 단위를 제공하여 개발 편의성을 극대화합니다.

### 4. 영속성 레이어: "Scene Template & Config 직렬화"
*   **결정:** `ISceneConfig` 인터페이스를 통해 전체 씬과 레이어 설정을 JSON으로 직렬화/역직렬화하는 기능을 공식화합니다.
*   **기능:**
    *   `getSceneConfig()`: 현재 편집 중인 전체 상태 추출.
    *   `loadSceneConfig()`: 해상도를 포함한 전체 프로젝트 복구.
    *   `loadTemplate()`: 기존 프로젝트의 하부에 특정 레이어 구조만 주입.

### 5. 가시적 스타일 확장: "텍스트 외곽선 및 비주얼라이저 모드"
*   **결정:** 기본 렌더링 품질 향상을 위해 텍스트 레이어에 외곽선(Stroke) 기능을 추가하고, 오디오 비주얼라이저에 다양한 렌더링 모드(Waveform, Circle)를 지원합니다.

## 결과 및 기대 효과 (Consequences)
1.  **성능 향상:** Registry 도입으로 수백 개의 레이어가 있는 복잡한 프로젝트에서도 UI 인스펙터 반응도가 유지됩니다.
2.  **안정성 확보:** 256바이트 표준화를 통해 하드웨어 가용성 문제가 해결되었으며, 고사양 셰이더 확장 기반이 마련되었습니다.
3.  **데이터 호환성:** 템플릿 시스템을 통해 프로젝트 저장/불러오기 및 사용자 프리셋 공유가 가능해졌습니다.

# ADR 008: Project Info, Settings, and Sequence Bounds Refactor (프로젝트 정보, 설정 및 시퀀스 범위 리팩토링)

[English](../en/008-project-info-settings-sequence-bounds-refactor.md)

- **상태**: 승인 및 구현 완료
- **날짜**: 2026-04-17
- **맥락**: `projectInfo` / `projectSettings`, 시퀀스 범위 유도, 스코프 마커 시맨틱에 대한 Rendium Engine 아키텍처 정리.

## 맥락

이전 아키텍처는 프로젝트 수준의 값들을 여러 최상위 manifest 필드에 분산해 유지하는 한편, `meta`는 관련 없는 문서 데이터들을 담는 무분별한 컨테이너로 사용되었습니다. 동시에 시퀀스 처리, 스코프 해석, 루트 스캐폴드 시맨틱 등이 셀렉터, 뮤테이터, UI 헬퍼 등에 산재해 있었습니다.

이로 인해 모델을 설명하고 진화시키는 것이 불필요하게 어려웠습니다:
- `meta`가 문서의 식별 정보와 프로젝트 설정을 모두 설명하기에 너무 포괄적이었습니다.
- 시퀀스 범위 및 부모 해석이 여러 곳에서 중복되어 유도되고 있었습니다.
- `scope:start` / `scope:end`는 레이어로 유지되었으나, 저장소와 UI 사이에서 일관되지 않게 처리되었습니다.
- 루트 스캐폴드(root scaffold)가 단순한 프로젝트 경계 센티넬 이상의 과도한 의미를 가지고 있었습니다.

## 결정 사항

다음과 같이 manifest 경계 및 유도 구조의 책임을 리팩토링합니다.

### 1. 프로젝트 DTO 정규화

`IProjectManifest`를 SSOT(Single Source of Truth)로 유지하되, 다음과 같이 구조화합니다:
- `projectInfo`
- `projectSettings`
- `layers`
- `layerOrder`

`projectInfo` 그룹은 이름, 타임스탬프와 같은 문서 식별 필드를 가지며, `projectSettings`는 캔버스, 배경색, 워터마크, 익스포트 범위, 작업 영역 설정을 가집니다.

### 2. 평탄한(Flat) 저장 모델 유지

새로운 `sequences` manifest 컬렉션을 만들지 않습니다.
- 시퀀스는 `layers + layerOrder`에 대한 계산된 래퍼(computed wrapper) 상태를 유지합니다.
- `scope:start` / `scope:end`는 호환성을 위해 레이어로 계속 저장됩니다.
- 시맨틱적으로 이들은 사용자 대면 콘텐츠 레이어가 아니라 구조 마커(structure marker)입니다.

### 3. 유도 구조 계산 분리

시퀀스 관련 유도 계산을 `EngineSelectors`에서 분리하여 전용 서비스로 이동시킵니다.
- 시퀀스 범위
- 부모 시퀀스 조회
- 삽입 맥락
- 유도된 재생 시간

`EngineSelectors`는 UI 스냅샷 및 뷰포트 지향 데이터 관리에 집중합니다.

### 4. 루트 스캐폴드 재정의

루트 스캐폴드를 프로젝트 경계 센티넬(sentinel)로 취급합니다.
- 구조적 정합성 및 복구를 지원합니다.
- 콘텐츠 레이어가 아닙니다.
- 독립적인 영속 사용자 개념이 아닙니다.

### 5. 빈 시퀀스 정책을 제품 레이어에 유지

저장 모델은 빈 시퀀스가 어떻게 표시될지 결정하지 않습니다.
- 제품/UI에서 플레이스홀더를 렌더링할 수 있습니다.
- 저장과 유도 계산은 구조적 정합성에만 집중합니다.

## 결과 및 영향

- 프로젝트 소유권 경계가 더 명확해집니다.
- 문서 형상이 명시적이므로 manifest 마이그레이션이 더 용이해집니다.
- 유도된 구조를 독립적으로 테스트하기가 쉬워집니다.
- UI는 시퀀스 범위를 다시 계산하지 않고 그대로 사용할 수 있습니다.
- 새로운 manifest 컬렉션을 추가하지 않고도 호환성을 보장합니다.

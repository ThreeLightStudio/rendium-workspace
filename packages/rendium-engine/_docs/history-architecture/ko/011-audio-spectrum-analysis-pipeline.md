# 011. Audio Spectrum Analysis Pipeline (오디오 스펙트럼 분석 파이프라인)

[English](../en/011-audio-spectrum-analysis-pipeline.md)

- **상태**: 코어 구현 승인 완료

## 맥락

현재의 스펙트럼 비주얼라이저는 오디오 분석 가정을 `SpectrumDrawableProvider` 내부와 결합하고 있습니다. 이 프로바이더는 FFT 데이터를 로컬에서 스무딩하고, 비주얼 밴드당 하나의 FFT 빈(bin) 위치만 샘플링한 다음, 전체 FFT 버퍼를 WebGPU에 업로드합니다.

이 방식은 네 가지 문제를 발생시켰습니다:
- 단일 빈 샘플링은 각 비주얼 밴드의 주파수 범위에 분산된 에너지를 놓치게 되며, 특히 넓은 고주파 밴드에서 이 문제가 심각해집니다.
- 대칭적인 스무딩(symmetric smoothing)은 에너지가 상승할 때와 하강할 때 동일한 반응 속도를 사용하므로, 어택(attack)이 뭉툭해지는 반면 릴리즈(release)는 음악적인 감쇄로 느껴지지 않습니다.
- 실시간 프리뷰와 오프라인 익스포트 간에 FFT 크기, 빈 개수, 샘플 레이트 및 데시벨 정규화가 하나의 공통 규약으로 표현되지 않아 편차가 발생할 수 있습니다.
- 동일한 오디오 소스에 연결된 여러 스펙트럼 레이어가 CPU 측 스무딩 및 데이터 준비 과정을 반복 수행하여, 처리된 프레임을 공유하지 못하고 불필요한 계산을 낭비합니다.

## 결정 사항

렌더러에 의존하지 않는 독립적인 오디오 스펙트럼 처리 규약 및 프로세서를 도입합니다.

`AudioSpectrumContract`는 FFT 크기, 샘플 레이트, 밴드 개수, 주파수 범위, 데시벨 범위, 밴드 스케일의 단일 진실 공급원(SSOT)이 됩니다. 최초로 지원되는 스케일은 기존 스펙트럼의 시각적 형태와 부합하는 `mel` 스케일이며, 향후 동일한 파이프라인 상에서 `octave` 및 `log` 스케일 전략도 지원 가능하도록 설계합니다.

`ISpectrumProcessor`는 정규화되지 않은 선형 강도(linear-magnitude) FFT 빈 데이터를 받아서 `BandFrame` DTO를 생성합니다. 프로세서는 다음 역할을 소유합니다:
- 규약에 따른 밴드 경계 계산,
- 각 밴드가 포함하는 FFT 빈 범위의 RMS 집계,
- `0..1` 범위로의 dB 정규화,
- 비대칭 어택/릴리즈 EMA 스무딩,
- 가비지 컬렉션(GC)을 최소화하는 프레임 생성을 위한 재사용 가능한 형식화 배열(typed-array) 저장소 관리.

비주얼 렌더러는 오직 `BandFrame` 데이터만을 소비합니다. 렌더러가 FFT 규약을 결정하거나, 밴드를 집계하거나, 시간적 동역학을 적용하지 않습니다.

## 데이터 흐름

이전 상태:
```text
AudioLayer / AudioManager
  -> 원시 또는 정규화된 FFT 데이터
  -> SpectrumDrawableProvider
  -> 프로바이더 로컬 스무딩 및 단일 빈 셰이더 샘플링
  -> GPU 버퍼 업로드
```

변경 후:
```text
AudioSource
  -> AudioSpectrumContract에 규격이 맞춰진 원시 선형 강도 FFT 데이터
  -> SpectrumProcessor
  -> 캐시된 BandFrame
  -> VisualRenderer / SpectrumDrawableProvider
  -> GPU 버퍼 업로드 및 인스턴싱 드로우
```

## 결과 및 영향

- 프리뷰와 익스포트가 병렬 상수를 사용하는 대신 동일한 FFT 규약에 따라 검증될 수 있습니다.
- 각 시각적 밴드가 단순히 하나의 샘플링된 빈이 아닌 RMS 범위를 나타내므로, 밴드 에너지가 소스 신호에 물리적으로 더 가까워집니다.
- 어택과 릴리즈 반응이 독립적으로 튜닝되어 더 날카로운 트랜지언트(transient)와 더 부드러운 감쇄(falloff)를 표현할 수 있습니다.
- 향후 여러 비주얼 스펙트럼 레이어가 연결된 오디오 소스 및 타임스탬프별로 하나의 정제된 `BandFrame`을 공유할 수 있습니다.
- 향후 옥타브 분할 밴드나 로그 밴드와 같은 다른 스케일을 추가할 때, 렌더러 코드를 건드리지 않고 밴드 경계 계산식만 교체하면 됩니다.
